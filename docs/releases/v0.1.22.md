# Orquestrador v0.1.22

## Resumo

A v0.1.22 separa a pasta de trabalho do orquestrador da pasta do projeto: em qualquer CLI, ele passa a iniciar no diretório temporário da sessão. Isso muda o contexto carregado automaticamente pelo orquestrador Claude; os executores continuam trabalhando no projeto com o contexto dele.

## Novidades

O orquestrador agora inicia em `%TEMP%\strategist-<id>` para qualquer CLI, em vez de iniciar na pasta do projeto. Antes, o orquestrador Codex já usava a pasta da sessão pelo argumento `-C` do adaptador. Ele mantém esse comportamento. A mudança efetiva de contexto é no orquestrador Claude, que deixa de carregar automaticamente as instruções `CLAUDE.md`, as skills locais de `.claude/skills`, o `.mcp.json` e os hooks e settings do projeto.

O Claude continua com o papel do orquestrador, as skills globais de `~/.agents`, os MCPs do usuário e o MCP do próprio app para delegar tarefas e aguardar resultados. Também continua podendo ler arquivos do projeto e executar Git nele para conferir o trabalho. A separação deixa as decisões de coordenação com o orquestrador e o contexto da codebase com os executores: estes continuam iniciando na pasta do projeto, com as instruções, skills, MCPs e hooks disponíveis ali, e recebem a tarefa delegada.

## Melhorias e correções

`CLAUDE_CODE_SANDBOXED=1`, que evita o diálogo de confiança na pasta do Claude Code, passa também a ser definido para o processo do orquestrador Claude. Antes, o app definia essa variável apenas para o executor Claude. Os executores e o orquestrador Codex não mudam de comportamento. Houve também um ajuste interno em `core.rs` para usar `is_multiple_of` e eliminar um aviso do clippy, sem efeito para quem usa o app.

## Impacto da atualização

Quem usa o orquestrador Claude e dependia de instruções, skills, MCPs ou hooks do projeto carregados automaticamente nele deixa de ter esse contexto no próprio orquestrador. Os executores continuam com o contexto do projeto e recebem apenas a tarefa que devem executar. O orquestrador ainda pode consultar os arquivos e o Git do projeto quando precisar verificar entregas. A atualização não exige migração de configuração nem dos projetos e não altera o comportamento do orquestrador Codex.

## Requisitos e limitações

Os requisitos gerais permanecem os mesmos da v0.1.21: Windows de 64 bits com WebView2; CLIs `claude` e `codex` instalados, autenticados e disponíveis no PATH quando forem usados; e Git no PATH, recomendado para os recursos que operam sobre o repositório. A atualização automática continua dependendo de internet e da validação da assinatura do instalador. A remoção do diálogo de confiança depende de `CLAUDE_CODE_SANDBOXED`, uma variável não documentada do Claude Code; ela pode mudar entre versões. As skills e configurações do projeto permanecem disponíveis para os executores.

## Instalação

Baixe [Orquestrador_0.1.22_x64-setup.exe](https://github.com/luansilvadb/orquestrador/releases/download/v0.1.22/Orquestrador_0.1.22_x64-setup.exe) na página da [release v0.1.22](https://github.com/luansilvadb/orquestrador/releases/tag/v0.1.22). A instalação continua sendo por usuário, sem administrador. Quem já tem o app recebe a atualização ao abri-lo: o atualizador consulta a última release estável, baixa o instalador, valida a assinatura, instala e reabre o programa.

## Comparação com a versão anterior

| Área | v0.1.21 | v0.1.22 |
| --- | --- | --- |
| Pasta inicial do orquestrador Claude | Pasta do projeto, com contexto do projeto carregado automaticamente | Pasta temporária da sessão, sem carregar automaticamente o contexto do projeto |
| Orquestrador Codex | Já usava a pasta da sessão por `-C` | Sem mudança de comportamento |
| Executores | Iniciavam na pasta do projeto com o contexto dela | Sem mudança de comportamento |
| Confiança do Claude Code | `CLAUDE_CODE_SANDBOXED=1` no executor Claude | A variável também é definida para o orquestrador Claude |

Diferença completa: [v0.1.21...v0.1.22](https://github.com/luansilvadb/orquestrador/compare/v0.1.21...v0.1.22).
