# Orquestrador v0.1.26

## Resumo

A v0.1.26 permite manter projetos em abas independentes e trabalhar com arquivos mesmo sem abrir uma pasta. Traz formatação de documentos, mais detalhes no grafo do Git e uma fila global para executores, além de ajustes em abas, abertura e operações de merge.

## Novidades

- **Projetos em abas:** a barra de título mostra cada pasta aberta, com seleção, fechamento e botão para abrir outra. As abas podem ser reordenadas arrastando. Cada projeto mantém seu próprio Core, orquestrador, executores, shells e estado do editor; a lista de projetos e a aba ativa são restauradas na próxima abertura do app.
- **Uso sem projeto:** quando não há projeto salvo para restaurar, o app abre numa tela limpa com a marca. O painel do Orquestrador e a faixa lateral ficam ocultos. É possível criar rascunhos, abrir arquivos soltos e salvá-los em qualquer pasta; abrir uma pasta cria uma aba de projeto.
- **Abertura animada:** a marca começa a animar antes de carregar a interface. O status acompanha a conexão e a reabertura das pastas salvas, e a animação respeita a preferência do Windows por movimento reduzido.
- **Barra de título e menu Arquivo:** a marca do app acompanha o menu com Novo arquivo, Abrir arquivo, Abrir pasta, projetos recentes, Salvar, Salvar como, Fechar pasta e Sair. O menu mostra os atalhos disponíveis, incluindo Ctrl+N, Ctrl+O e Ctrl+K, Ctrl+O para abrir uma pasta.
- **Abertura pelo Explorer:** o instalador adiciona opções para abrir arquivos e pastas com o Orquestrador. Se o app já estiver aberto, os caminhos chegam à janela existente; pastas viram projetos e arquivos são abertos no editor.
- **Listas e ordem das abas:** editor, painel do Orquestrador e Terminal usam a mesma lista “Todas as abas”, com indicação da aba ativa e fechamento da linha destacada pelo X ou pela tecla Delete. Abas de projeto, do editor e do Terminal podem ser reordenadas arrastando; o botão + do Terminal fica logo após a última aba.
- **Formatar Documento:** Shift+Alt+F e o menu de contexto formatam o buffer aberto sem salvá-lo automaticamente. O Prettier integrado atende JavaScript/JSX, TypeScript/TSX, CSS/SCSS/Less, HTML/Vue, JSON/JSONC/JSON5, Markdown e YAML; Python usa ruff ou black, Rust usa rustfmt e Go usa gofmt. A formatação considera configurações Prettier e opções reconhecidas do EditorConfig, e mantém o cursor e a seleção. Arquivos sem suporte, não salvos ou somente leitura não podem ser formatados.
- **Detalhes no grafo Git:** ao passar o cursor sobre um commit, o cartão mostra autor, datas, mensagem, coautores e estatísticas de arquivos e linhas. Também permite copiar o hash e, quando a origem é do GitHub, abrir o commit no navegador. Ao abrir o grafo, a área dele divide o espaço igualmente com a lista de arquivos; arrastar o divisor define outra proporção.
- **Fila de executores:** a capacidade é compartilhada pelos projetos abertos e calculada pela CPU e pela memória. Executores sem vaga aguardam e começam quando uma vaga é liberada.

## Melhorias e correções

- Fechar uma aba de projeto consulta as alterações não salvas e o trabalho daquele projeto, incluindo executores na fila. Fechar a janela consulta as alterações dos projetos montados. Salvar, descartar ou cancelar as alterações mantém a recuperação do editor; encerrar um projeto também fecha seus terminais. Ao fechar o último Terminal, a lista some sem deslocar o menu.
- Os números exibidos para executores e terminais passam a usar o menor número livre, que pode ser reutilizado quando uma aba fecha. No terminal do Codex, a roda do mouse volta a rolar o histórico.
- Filtros de caminho com `*` e `?` terminam no fim do nome: `*.js`, por exemplo, não corresponde a `package.json`. O Ctrl+P verifica no disco apenas os resultados que podem entrar na lista.
- O Git agora permite concluir um merge cujo resultado ficou igual ao HEAD e exibir conflitos mesmo quando a base não pode ser lida. A gravação do editor preserva o fim de linha escolhido; preparar trechos e gravar resolução recusam arquivos com CRLF e LF misturados, sem reescrever o índice ou o arquivo.
- A configuração é gravada por arquivo temporário e renomeação, para que uma interrupção durante a gravação deixe a versão anterior disponível.

## Impacto da atualização

Sem projetos abertos salvos, o app passa a iniciar sem exigir a escolha de uma pasta; projetos que estavam abertos são restaurados em abas. Cada projeto tem sua sessão de execução isolada, mas todos compartilham o teto de executores. Se CPU ou memória não puderem ser lidas, o teto fica em no máximo dois; executores adicionais aguardam vaga.

Os CLIs são iniciados pelos binários nativos `claude.exe` e `codex.exe`; os atalhos `.cmd` do npm não substituem esses executáveis no terminal. Arquivos abertos fora de um projeto podem ser salvos fora dele, mas não recebem recursos de Git do projeto. Fechar uma aba de projeto com trabalho ativo agora pede confirmação antes de encerrar seus processos.

## Requisitos e limitações

O app continua voltado ao Windows de 64 bits com WebView2. A ferramenta escolhida para cada papel precisa estar instalada, autenticada e disponível no PATH como `claude.exe` ou `codex.exe`; o Git no PATH é necessário para os recursos de repositório. Os formatadores ruff, black, rustfmt e gofmt são dependências opcionais e precisam estar no PATH para os respectivos tipos de arquivo. Arquivos sem formatador compatível continuam editáveis sem formatação automática. A atualização automática requer internet e validação da assinatura do instalador.

## Instalação

Baixe [Orquestrador_0.1.26_x64-setup.exe](https://github.com/luansilvadb/orquestrador/releases/download/v0.1.26/Orquestrador_0.1.26_x64-setup.exe) na página da [release v0.1.26](https://github.com/luansilvadb/orquestrador/releases/tag/v0.1.26). Quem já tem o app recebe a atualização ao abri-lo; o atualizador consulta a release estável, baixa o instalador, valida a assinatura, instala e reabre o programa.

## Comparação com a versão anterior

| Área | v0.1.25 | v0.1.26 |
| --- | --- | --- |
| Projetos | Um projeto ativo por vez | Abas com Core e sessão de execução separados por projeto |
| Início sem projeto | Abertura começava pela escolha da pasta | Tela limpa, rascunhos e arquivos soltos; projetos abertos são restaurados |
| Barra de título | Sem abas de projeto e com menu hambúrguer | Marca, menu Arquivo e abas de projeto arrastáveis |
| Abas de editor e Terminal | Sem reordenação por arrasto e sem lista comum | Reordenação no projeto, editor e Terminal; listas “Todas as abas” compartilhadas |
| Formatação | Sem comando Formatar Documento | Prettier integrado e suporte a ruff, black, rustfmt e gofmt |
| Grafo Git | Commit e arquivos na área do grafo | Divisão inicial igual e cartão de detalhes no hover |
| Executores | Teto calculado dentro da sessão do projeto | Teto e fila globais entre projetos |
| Explorer | Sem abertura integrada pelo menu de contexto | Opções para abrir arquivos e pastas com o Orquestrador |
| Merge e fim de linha | Merge igual ao HEAD não concluía; fim misto podia ser convertido | Merge conclui e arquivos mistos são recusados sem conversão |
