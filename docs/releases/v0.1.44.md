# Orquestrador v0.1.44

## Resumo

A v0.1.44 deixa o app leve com muitas alterações pendentes no Git. Os spinners ociosos dos botões param de girar escondidos e a lista de alterações do painel Git passa a montar só as linhas visíveis, então a tela não trava mais com milhares de arquivos alterados.

## Novidades

- **Lista de alterações virtualizada.** No painel Git, as seções Preparadas e Alterações montam só as linhas visíveis, com folga de 10 linhas acima e abaixo. Na medição, eram 26 linhas montadas para qualquer número de alterações. A rolagem, o clique, o Ctrl+clique e o menu de contexto continuam como antes.

## Melhorias e correções

- **Spinner ocioso parado.** O Button do `@lobehub/ui` 5.58.0, base do ActionIcon, mantém um spinner montado com animação infinita mesmo sem loading. Cada linha da lista de alterações tem dois, e a tela Git fica montada (escondida) nas outras telas, então o navegador recalculava o estilo a cada quadro e cada mudança no status redesenhava todas as linhas. Uma regra CSS global em `src/index.css` para o spinner ocioso (o slot com `aria-hidden="true"`); com loading ele continua girando. Vale para todos os ActionIcon e Button do app.
- O `git status`, o IPC e a comparação do status não eram o gargalo: o `git status` levou 49 ms com 500 alterações e 103 ms com 30000.
- Teste novo em `tests/check-git-ui.mjs` com 5000 alterações (fixture `__mock.addGitFiles` no mock): confere zero animações infinitas nas telas Git e Arquivos, no máximo 100 linhas montadas, a rolagem até o fim e o Ctrl+clique com menu de contexto.

### Medição

Build de medição (debug com o frontend de produção embutido), em repositório sintético com metade dos arquivos rastreados e modificados e metade não rastreados, com o status estável ou com um arquivo mudando a cada segundo. Os números não são garantia: dependem da máquina. Valores em ms, salvo indicação, antes e depois:

- Quadros por segundo em repouso na tela Arquivos: 1000 alterações, 25 para 258; 2000, 12 para 255; 5000, 4,3 para 258; 10000, 1,7 para 261.
- Pior quadro na tela Git com um arquivo mudando por segundo: 1000, 417 para 21; 5000, 2671 para 50; 10000, 5083 para 71.
- Latência de tecla (p95) no campo de mensagem do commit, com arquivos mudando: 1000, 413 para 7; 2000, 899 para 7; 5000, 39220 para 9; 10000, 82338 para 7.
- Abrir a tela Git: 1000, 761 para 39; 2000, 1568 para 30; 5000, 4066 para 46; 10000, 7944 para 46.
- Nós DOM com 5000 alterações: de 126 mil para cerca de 2 mil. Animações infinitas ativas depois: 0.
- Com muitos terminais (2000 alterações pendentes, um arquivo mudando por segundo e 200 linhas/s de saída por terminal), só depois da correção: 4, 8 e 16 terminais com eco p95 de 27, 27 e 28 ms, cerca de 230 fps e RAM total de 782, 1135 e 1782 MB (cerca de 83 MB por terminal, incluindo o pwsh e o gerador de saída do teste). Com 16 terminais a 2000 linhas/s: eco p95 de 38 ms, 229 fps e RAM de 2647 MB (pico de 3666).

## Impacto da atualização

Nenhuma mudança de configuração ou de dados. `%LOCALAPPDATA%\orquestrador\config.json`, os formatos persistidos e os arquivos dos projetos ficam como estão, e o instalador novo é aplicado pelo próprio app ao abrir, como nas versões anteriores. O que muda é a renderização da lista de alterações do Git e a animação dos botões ociosos.

## Requisitos e limitações

O instalador é para Windows de 64 bits com WebView2. A atualização automática consulta a última release estável no GitHub, baixa o instalador e valida a assinatura. Limites reais:

- Na lista virtualizada, uma linha focada que sai da vista é desmontada e perde o foco, e o Tab percorre só as linhas montadas.
- A regra CSS depende da estrutura interna do Button do `@lobehub/ui` 5.58.0. Se uma atualização a mudar, o teste novo acusa.
- Não houve medição de digitação no editor nem no terminal com muitas alterações, só no campo de mensagem do commit.
- Os números da seção Medição vêm de um cenário sintético, em um build de medição, e não de uso real.

## Instalação

Baixe [Orquestrador_0.1.44_x64-setup.exe](https://github.com/luansilvadb/orquestrador/releases/download/v0.1.44/Orquestrador_0.1.44_x64-setup.exe) na página da [release v0.1.44](https://github.com/luansilvadb/orquestrador/releases/tag/v0.1.44), após sua publicação. Quem já tem o aplicativo instalado recebe a atualização ao abri-lo: ele consulta a última release estável, baixa e verifica o instalador, instala e reabre o programa.
