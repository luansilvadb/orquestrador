# Orquestrador v0.1.23

## Resumo

A v0.1.23 é uma versão de manutenção: reorganiza o código do aplicativo por dentro, sem mudança visível na interface nem no comportamento do orquestrador. Ela não exige ação de quem já usa a v0.1.22, mas deixa o projeto mais fácil de manter e prepara o caminho para macOS e Linux.

## Novidades

Não há funcionalidade nova para o usuário nesta versão. Os recursos do app são os mesmos da v0.1.22.

## Melhorias e correções

O código da interface foi organizado em pastas por área (backend, editor, explorer, git, search, terminal, window e shared), o que facilita localizar e alterar cada parte do app. A comunicação entre a interface e o backend passou a ser descrita por um mapa tipado único, com os 56 comandos do backend. O contrato é conferido pelo `tsc` e pela checagem `scripts/check-commands.mjs`. O código específico do Windows foi isolado na pasta `src-tauri/src/platform/`, primeiro passo para suportar macOS e Linux. Para quem usa o app no Windows, nada disso muda o resultado.

O projeto ganhou os comandos `npm run check` e `npm run check:ui`, que rodam as checagens de código e de interface. Um fluxo de integração contínua (`.github/workflows/ci.yml`) roda a cada push e pull request: no Windows, executa o build do front-end, o `npm run check` e os testes do backend Rust; no Ubuntu e no macOS, faz o build do front-end e compila o backend, sem checagens nem testes. O `npm run check:ui` não roda no CI.

## Impacto da atualização

Não há migração de configuração, de projetos nem de arquivos. O comportamento padrão do app é o mesmo da v0.1.22, e a atualização automática segue o mesmo caminho: quem já tem a versão anterior recebe a nova ao abrir o app.

## Requisitos e limitações

Os requisitos continuam os da v0.1.22: Windows de 64 bits com WebView2; CLIs `claude` e `codex` instalados, autenticados e disponíveis no PATH quando forem usados; e Git no PATH, recomendado para os recursos que operam sobre o repositório. A atualização automática depende de internet e da validação da assinatura do instalador.

macOS e Linux ainda não têm os recursos do app. Nesses sistemas o CI apenas compila o backend, para garantir que o código continue portável.

## Instalação

Baixe [Orquestrador_0.1.23_x64-setup.exe](https://github.com/luansilvadb/orquestrador/releases/download/v0.1.23/Orquestrador_0.1.23_x64-setup.exe) na página da [release v0.1.23](https://github.com/luansilvadb/orquestrador/releases/tag/v0.1.23). A instalação continua sendo por usuário, sem administrador. Quem já tem o app recebe a atualização ao abri-lo: o atualizador consulta a última release estável, baixa o instalador, valida a assinatura, instala e reabre o programa.

## Comparação com a versão anterior

| Área | v0.1.22 | v0.1.23 |
| --- | --- | --- |
| Recursos e comportamento visível do app | Recursos da v0.1.22 | Sem mudança |
| Organização do front-end (`src/`) | Arquivos em uma pasta única | Pastas por área: backend, editor, explorer, git, search, terminal, window e shared |
| Contrato entre front-end e backend | Chamadas aos comandos sem tipagem central | Mapa tipado `Commands`, conferido pelo `tsc` e por `scripts/check-commands.mjs` |
| Código específico do Windows | Espalhado pelo backend | Isolado em `src-tauri/src/platform/` |
| Checagens e CI | Sem comando único de checagem nem CI a cada push | `npm run check` e `npm run check:ui`; CI a cada push e pull request, com build, checagens e testes Rust no Windows e compilação do backend no Ubuntu e no macOS |
| macOS e Linux | Sem recursos; sem compilação no CI | Sem recursos; o CI compila o backend nesses sistemas |
